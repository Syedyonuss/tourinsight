# TourInsight 3.5 — deployment guide (Vercel + Render)

TourInsight is a full-stack FastAPI + HTML/CSS/JavaScript application. Vercel hosts the static frontend; Render runs the FastAPI backend and provides a persistent disk for SQLite and uploaded images.

## Important cost / persistence note

The Render service in `render.yaml` uses the `starter` plan and a 1 GB persistent disk. A persistent disk is necessary for SQLite user accounts, saved itineraries, community posts and uploaded photos to survive service restarts and deployments. Do not change this to an ephemeral/free instance for a real deployment. Check Render's current pricing before creating the service.

## Step 1 — Put the project on GitHub

1. Extract the deployment ZIP.
2. Open `tourinsight_local`.
3. Go to GitHub and create a **new empty repository** named `tourinsight` (do not add a README, licence or .gitignore there).
4. On the new repository page choose **Add file → Upload files**.
5. Drag the *contents* of the extracted `tourinsight_local` folder into the upload area (not the enclosing folder).
6. Commit the files to the `main` branch.

Never upload `.env`, passwords, API keys, local database files or real user uploads. `.gitignore` excludes these.

## Step 2 — Deploy the backend on Render

1. Sign in to Render using the same GitHub account.
2. Choose **New → Blueprint** and connect the `tourinsight` repository.
3. Render should detect `render.yaml`. Review the service and persistent disk, then apply the Blueprint.
4. Wait for the service to finish deploying.
5. Copy the backend URL, for example `https://tourinsight-api-xxxx.onrender.com`.
6. Test `https://YOUR-RENDER-HOST/api/health`. It should return JSON with `"status":"ok"` and an active destination count.

The database starts with the built-in Karnataka destination catalogue. The local development SQLite database is intentionally not uploaded.

## Step 3 — Connect Vercel to Render

1. In GitHub, open `vercel.json` in the `tourinsight` repository and choose the edit (pencil) button.
2. Replace **all three** occurrences of `https://REPLACE-WITH-YOUR-RENDER-SERVICE.onrender.com` with your actual Render service origin (no trailing slash).
3. Commit the change.

## Step 4 — Deploy the frontend on Vercel

1. Sign in to Vercel with GitHub.
2. Choose **Add New → Project** and import the `tourinsight` repository.
3. Framework Preset: **Other**.
4. Root Directory: `web` is **not** the project root; leave the project root as `./`.
5. In Build & Output Settings, set **Output Directory** to `web`. Leave Build Command empty and Install Command empty.
6. Deploy. Vercel will provide a public `https://...vercel.app` URL.

Because Vercel rewrites `/api`, `/uploads` and `/shared` to Render, browser requests remain same-origin and session cookies can work on the Vercel domain.

## Step 5 — Verify

- Open the Vercel URL and hard-refresh.
- Open `/api/health` on the Vercel domain; it should return the Render health JSON.
- Register a test account and sign in.
- Save a test itinerary, refresh, and verify it remains.
- If uploads are enabled, upload a test image and verify it remains after a Render restart.

## Security / operations

- Keep `SESSION_SECRET` generated by Render; do not replace it with a public value.
- The SQLite database and uploaded images live on Render's persistent disk at `/var/data`.
- Back up `/var/data/tourinsight.db` and `/var/data/uploads` regularly. A persistent disk is not itself a backup.
- The application currently uses SQLite. If traffic or concurrent writes grow substantially, migrate to managed PostgreSQL and object storage.
- Live hotel inventory, verified bookings and live Reddit ingestion are not included just because the site is deployed; those require separate provider integrations and credentials.
